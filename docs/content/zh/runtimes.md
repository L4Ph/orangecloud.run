# 深入运行时：isolate 究竟做了什么

“V8 isolate”听起来像在说速度，实际上说的是 Workers **省略了什么**，而这决定了你什么时候该换工具。

## 进程与 isolate

Node.js 在一个进程里运行一个 V8 isolate，外面还有 libuv 的事件循环、线程池、文件描述符和套接字。每个请求起一个进程太重，于是大家共用一个——状态和权限也一起共用。

Worker **只有 isolate**。没有进程、没有套接字、没有文件；外部世界只有 `fetch()` 和绑定。所以一台机器能塞下上千个 isolate，启动只要毫秒。不共享状态既是安全模型，也是密度来源。

## JIT 与启动时间

V8 先以字节码运行，只把热点函数编译成机器码。isolate 的启动就是“分配堆 + 编译脚本”，没有进程创建和镜像解包。这正是与容器的决定性差距。

|      | isolate         | 容器             |
| ---- | --------------- | ---------------- |
| 启动 | 毫秒级          | 数百毫秒到数十秒 |
| 隔离 | 堆与能力        | 内核命名空间     |
| 能做 | Web 标准 + 绑定 | 几乎任何事       |
| 计费 | 请求 + CPU 毫秒 | 运行时间 + 内存  |

## 限制决定设计

- 内存 128MB：不要放巨型数组，用流
- CPU 30 秒（付费，最多 5 分钟）：等待免费，计算收费
- 没有文件系统：临时数据放 R2 或 KV
- 子请求上限：一次请求不要扇出几百个外部调用

`nodejs_compat` 能补上部分 Node API，但没有 `fs`。真正需要时才是容器的舞台。

## 何时分叉

1. 等 HTTP、查数据库、少量计算 → **isolate**
2. 原生二进制、重依赖、超过 128MB、常驻进程 → **容器**
3. 几分钟到几天的编排 → **Workflows**
4. 同一时刻只能有一个执行 → **Durable Objects**

先问“能不能用 Worker 写”，架构就会保持很小。

# AI Gateway

外部の LLM プロバイダや Workers AI をフロントエンドやバックエンドから直接叩く設計は、運用フェーズに入った途端に脆弱性を露呈する。上流 API の突発的な障害、同一プロンプトに対する重複リクエストによる課金の浪費、そして悪意あるユーザーによる過剰なトークン消費。これらをアプリケーションコード側の個別ロジックで受け止めるのは限界がある。

AI Gateway は、モデル呼び出しの**直前に配置するリバースプロキシ**である。推論処理そのものは行わず、OpenAI、Anthropic、Google Gemini、Workers AI へ向かう通信を一元的に仲介し、可観測性とコスト防壁を提供する。

## もたらされる 5 つの防壁

1. **完全なリクエスト監査**: どのアカウントがいつ、どのモデルに対して何トークンを消費したかの全履歴をダッシュボードへ記録する。
2. **意味的・完全一致キャッシュ**: 同一のプロンプトとパラメータに対する推論結果をエッジにキャッシュし、2 度目以降の呼び出しをプロバイダへ通さずミリ秒で返す。トークン課金と通信時間を同時にゼロへ削減できる。
3. **細粒度のレートリミット**: ユーザー単位や IP 単位で 1 分あたりの実行回数上限を強制し、ボットや暴走ループによる請求事故を水際で遮断する。
4. **自動フォールバックと再試行**: 優先モデル（例: 低コストなモデル）が 500 エラーを返した際、透過的に代替プロバイダのモデルへリクエストを転送する。
5. **予算上限とアラート**: 月間のコストが指定額に達した時点で自動的に呼び出しを拒否するフェイルセーフを設ける。

## 導入手法

導入にあたって特別な SDK は必須ではない。既存の API クライアントや `fetch` 呼び出しの向く先を、AI Gateway のエンドポイント URL へ差し替えるだけで完結する。

```js
const response = await fetch(
  `https://gateway.ai.cloudflare.com/v1/${env.CF_ACCOUNT_ID}/${env.AI_GATEWAY_NAME}/anthropic/v1/messages`,
  {
    method: 'POST',
    headers: {
      'content-type': 'application/json',
      'x-api-key': env.ANTHROPIC_API_KEY,
    },
    body: JSON.stringify({
      model: 'claude-3-5-haiku-20241022',
      max_tokens: 256,
      messages: [{ role: 'user', content: 'Workers の特徴を要約してください。' }],
    }),
  },
);
```

## コストを抑え込むための設計原則

- **既定値は最小・最安のモデルに固定する**: 全てのリクエストに最高性能のモデルを割り当てず、高度な推論を要する特定の機能にのみフラグで切り替える。
- **入力テキスト長の上限バリデーション**: クライアントから送られた巨大なテキストをそのままプロバイダへ流さず、Worker の手前で文字数やトークン数を打ち切る。
- **キャッシュの生存期間（TTL）を意識する**: リアルタイム性を求めない分析や要約タスクには長めのキャッシュを設定し、エッジから即答させる。

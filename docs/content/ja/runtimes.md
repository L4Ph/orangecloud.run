# ランタイムの深掘り: isolate は何をしているか

「V8 isolate」と聞いても、速い・安い以外の実体が見えないと設計判断はできません。ここでは Workers が何を省略しているのかを、Node.js との差分で整理します。

## プロセスと isolate

Node.js は 1 プロセスに 1 つの V8 isolate を持ち、その外側に libuv のイベントループ、スレッドプール、ファイルディスクリプタ、ソケットがあります。リクエストごとにプロセスを立てると重いので、みんなで 1 つを共有します。その代わり、状態も権限も共有されます。

Workers は **isolate だけ**を持ちます。プロセスもソケットもファイルもなく、外部との接続は `fetch()` とバインディングに限られます。だから 1 台のマシンに数千の isolate を載せられ、起動がミリ秒で済みます。状態を共有しないことが、そのまま安全と密度になっています。

## JIT と起動時間

V8 は最初にバイトコードで走らせ、ホットな関数だけを JIT で機械語にします。isolate の起動は「V8 のヒープを作る + スクリプトをコンパイルする」だけで、プロセスの起動やイメージの展開がありません。ここがコンテナとの決定的な差です。

|            | isolate                   | コンテナ          |
| ---------- | ------------------------- | ----------------- |
| 起動       | 数 ms                     | 数百 ms〜数十秒   |
| 分離       | ヒープと権限              | カーネル名前空間  |
| できること | Web 標準 + バインディング | なんでも          |
| 課金       | リクエスト + CPU ms       | 実行時間 + メモリ |

## 制限が設計を決める

- メモリ 128MB: 大きな配列を扱う処理は向かない。ストリームで流す
- CPU 30 秒（有料、最大 5 分）: 「待つ」は無料、「計算する」が高い
- ファイルなし: 一時ファイルが必要なら R2 か KV に置く
- サブリクエスト上限: 1 リクエストで何百回も外部 API を叩かない

Node の API が必要な場面は `nodejs_compat` フラグで一部埋まりますが、`fs` はありません。どうしても必要なときがコンテナの出番です。

## どこで分岐するか

1. HTTP を待つ、DB を引く、少し計算する → **isolate**
2. ネイティブバイナリ、重い依存、128MB 超、常駐プロセス → **コンテナ**
3. 数分〜数日の段取り → **Workflows**
4. 同時実行を 1 つに絞る → **Durable Objects**

「まず isolate で書けるか考える」を習慣にすると、構成が小さく保てます。

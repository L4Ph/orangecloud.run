# 런타임 깊이 보기: isolate는 무엇을 하는가

"V8 isolate"는 빠르다는 주장처럼 들리지만, 실제로는 Workers가 **무엇을 생략했는지**에 대한 말입니다. 그 생략이 언제 다른 도구로 넘어가야 하는지를 알려줍니다.

## 프로세스와 isolate

Node.js는 한 프로세스 안에 V8 isolate 하나를 두고, 바깥에 libuv 이벤트 루프와 스레드 풀, 파일 디스크립터, 소켓을 둡니다. 요청마다 프로세스를 띄우기는 무거워서 모두가 하나를 공유하고, 그와 함께 상태와 권한도 공유됩니다.

Worker는 **isolate만** 가집니다. 프로세스도 소켓도 파일도 없고, 외부와의 연결은 `fetch()`와 바인딩뿐입니다. 그래서 한 머신에 수천 개를 올릴 수 있고 기동이 밀리초입니다. 상태를 공유하지 않는 것이 곧 안전 모델이자 밀도입니다.

## JIT와 기동 시간

V8은 먼저 바이트코드로 실행하고 뜨거운 함수만 기계어로 컴파일합니다. isolate 기동은 "힙 할당 + 스크립트 컴파일"뿐이고, 프로세스 생성이나 이미지 해제가 없습니다. 컨테이너와의 결정적 차이가 여기입니다.

|           | isolate          | 컨테이너            |
| --------- | ---------------- | ------------------- |
| 기동      | 밀리초           | 수백 밀리초~수십 초 |
| 격리      | 힙과 권한        | 커널 네임스페이스   |
| 가능한 일 | 웹 표준 + 바인딩 | 무엇이든            |
| 과금      | 요청 + CPU ms    | 실행 시간 + 메모리  |

## 제한이 설계를 정한다

- 메모리 128MB: 거대한 배열은 불가. 스트림으로 흘리기
- CPU 30초(유료, 최대 5분): 기다리는 건 무료, 계산은 비쌈
- 파일 없음: 임시 데이터는 R2나 KV로
- 서브리퀘스트 한도: 한 요청에서 외부 API를 수백 번 부르지 않기

`nodejs_compat`가 Node API 일부를 채우지만 `fs`는 없습니다. 정말 필요할 때가 컨테이너의 자리입니다.

## 분기 지점

1. HTTP 대기, DB 조회, 약간의 계산 → **isolate**
2. 네이티브 바이너리, 무거운 의존성, 128MB 초과, 상주 프로세스 → **컨테이너**
3. 몇 분~며칠의 단계적 작업 → **Workflows**
4. 동시 실행을 하나로 → **Durable Objects**

"먼저 Worker로 쓸 수 있는지" 묻는 습관이 구조를 작게 유지합니다.

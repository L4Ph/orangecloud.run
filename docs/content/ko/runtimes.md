# 런타임 구조 비교 (Node.js와 V8 isolate)

서버 측 JavaScript의 역사는 오랫동안 Node.js의 아키텍처와 동일시되어 왔다. 하지만 엣지 컴퓨팅이 요구하는 '극소의 기동 시간', '극도로 높은 수용 밀도', '안전한 멀티테넌트 격리' 앞에서 Node.js의 전제 구조는 큰 걸림돌이 된다.

Cloudflare Workers를 뒷받침하는 **V8 isolate**가 무엇을 걷어내고 무엇을 남겼는지 이해함으로써, 엣지에서의 정확한 설계 판단이 가능해진다.

## 프로세스 모델과 격리 아키텍처의 근본적 차이

Node.js는 하나의 OS 프로세스에 하나의 V8 인스턴스를 할당한다. 그 외부에는 libuv의 이벤트 루프, 멀티스레드 풀, 파일 디스크립터 테이블, 그리고 raw 소켓 관리 메커니즘이 얽혀 있다. 이 구조는 하나의 프로세스를 영속적으로 상주시키는 것을 전제로 하며, 요청마다 프로세스를 신설·파기하는 운영 방식에는 도저히 견딜 수 없다.

```
[Node.js의 프로세스 구조]
OS 프로세스 ── libuv (C++ / 스레드 풀 / 파일 I/O / 네트워크 소켓)
             └── 단일 V8 인스턴스 (모든 요청에서 힙·상태를 공유)

[Workers의 isolate 구조]
단일 호스트 프로세스 ── 격리 경계 (메모리 보호·권한 샌드박스)
                      ├── isolate A (사용자 A의 힙 / 독립 메모리 공간)
                      ├── isolate B (사용자 B의 힙 / 독립 메모리 공간)
                      └── isolate C (사용자 C의 힙 / 독립 메모리 공간)
```

Cloudflare Workers는 OS 프로세스 레이어를 완전히 은폐하고, **V8 isolate 단독**을 실행의 기본 단위로 취급한다. 호스트 머신의 단일 프로세스 내에 메모리 공간이 엄격히 분리된 수천 개의 isolate를 빈틈없이 채워 넣는다.

파일 시스템 액세스나 소켓의 직접 제어와 같은 특권적인 시스템 콜을 미리 박탈함으로써, 타인의 코드가 동일 호스트 내의 인접한 메모리 영역을 엿볼 리스크를 근본적으로 배제한다.

## 콜드 스타트의 물리적 한계

컨테이너(Docker 등)의 기동에는 컨테이너 이미지의 레이어 풀링, Linux 네임스페이스(Namespace) 초기화, 가상 네트워크 인터페이스 구성, 그리고 게스트 프로세스 기동이라는 일련의 단계가 필수적이며, 아무리 최적화해도 수백 밀리초에서 수 초의 시간이 소요된다.

이에 반해 isolate의 기동은 'V8 힙 영역의 초기화'와 '사전 컴파일된 바이트코드 로드'만으로 완료된다. 네트워크나 가상 머신의 부팅 시퀀스가 존재하지 않으므로, 물리적 제약으로서 1~5밀리초 이내에 요청 처리를 시작할 수 있다.

## 아키텍처 선정 경계

| 처리 성격                                  | 최적의 선택지             | 근거                                            |
| ------------------------------------------ | ------------------------- | ----------------------------------------------- |
| Web API, 경량 비즈니스 로직, 데이터 중계   | **V8 isolate(Workers)**   | 기동이 밀리초 단위이며, 아이들 비용이 제로      |
| 장시간 동작하는 배치, FFmpeg, Playwright   | **Cloudflare Containers** | 완전한 Linux 커널과 바이너리 실행 환경이 필수적 |
| 외부와의 연결 대기(DB 쿼리, 외부 REST API) | **V8 isolate(Workers)**   | CPU 시간 과금이므로 네트워크 대기 시간은 무료   |
| 단일 리소스로의 직렬화 및 배타적 제어      | **Durable Objects**       | 전 세계에서 하나의 인스턴스로 요청을 집약       |

Node.js용 라이브러리를 가져올 때는 `nodejs_compat` 호환 플래그를 이용할 수 있지만, 이를 통해 제공되는 것은 `Buffer`, `crypto`, `events` 등 Web 표준에 가까운 일부 추상 계층에 불과하다. `fs`를 통한 로컬 디스크 조작을 전제로 한 설계는 isolate의 이념과 근본적으로 양립할 수 없다.

# D1（无服务器关系型数据库）

在尝试使用无服务器架构处理关系型数据库时，长期以来一直面临两大障碍：长距离网络带来的通信延迟，以及连接池（Connection Pool）的耗尽。

D1 是一个使用 **SQLite** SQL 的无服务器数据库。默认由一个位置上的单个主节点（Primary）处理所有查询，因此距离较远的位置仍会有通信延迟。启用读取副本（Read Replica）并使用 Sessions API（`withSession()`）后，读取查询可以分散到全球各地的副本。写入始终在主节点上执行。

## 查询执行的 3 大原则

```js
// 定义表或执行迁移
await env.DB.prepare("CREATE TABLE IF NOT EXISTS notes (id INTEGER PRIMARY KEY, body TEXT)").run();

// 使用占位符进行安全的参数注入
await env.DB.prepare("INSERT INTO notes (body) VALUES (?)").bind("hello").run();

// 获取搜索结果
const { results } = await env.DB.prepare("SELECT * FROM notes").all();
```

- 严禁通过字符串拼接来构建 SQL。使用 `prepare(...).bind(...)` 将转义处理交给驱动程序，从而消除 SQL 注入的漏洞。
- `exec()` 具有**以换行符分割语句后执行**的特性。如果传递跨多行的复杂 DDL，语句会在意想不到的位置被截断，从而导致语法错误。将 DDL 也通过 `prepare(...).run()` 作为单条语句传递更为稳健。
- 获取多行数据时调用 `all()`，仅提取首行时调用 `first()`。

## 计费模型的关键点

在 D1 的计费体系中，最需要注意的指标并非查询发起次数，而是**从磁盘读取的行数和写入的行数**。

如果 `WHERE` 子句的目标列没有建立索引，数据库将执行对整个表的全表扫描。对于一个包含 10 万行的表，仅一次简单的搜索就会产生 10 万行的读取费用。绝不能忽略 `CREATE INDEX` 的设计。

| 操作类型 | 免费额度    | 付费方案                      |
| -------- | ----------- | ----------------------------- |
| 读取行数 | 500 万行/日 | 250 亿行/月以内（含基本费）   |
| 写入行数 | 10 万行/日  | 5,000 万行/月以内（含基本费） |

编辑器中的 `env.DB` 通过 RPC 转发到真实的 D1，运行的是同一个 SQLite 查询引擎。可用的只有 `prepare()`（及 `bind()` / `run()` / `all()` / `raw()` / `first()`）和 `exec()`，没有 `batch()` 和 `withSession()`。该数据库由本站的所有用户共用。

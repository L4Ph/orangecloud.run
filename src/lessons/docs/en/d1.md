# D1 (Serverless Relational Database)

Attempting to handle relational databases within a serverless architecture has long been hindered by two hurdles: communication latency due to long-distance networking and the exhaustion of connection pools.

D1 is a serverless database that uses the SQL of **SQLite**. By default a single primary in one location processes every query, so latency remains for distant locations. If you enable read replication and use the Sessions API (`withSession()`), read queries can be distributed across read replicas worldwide. Writes always run on the primary.

## Three Principles of Query Execution

```js
// Define tables or execute migrations
await env.DB.prepare("CREATE TABLE IF NOT EXISTS notes (id INTEGER PRIMARY KEY, body TEXT)").run();

// Safe parameter injection using placeholders
await env.DB.prepare("INSERT INTO notes (body) VALUES (?)").bind("hello").run();

// Fetch search results
const { results } = await env.DB.prepare("SELECT * FROM notes").all();
```

- Assembling SQL via string concatenation is strictly prohibited. Use `prepare(...).bind(...)` to delegate escaping to the driver, eliminating SQL injection vulnerabilities.
- `exec()` has the quirk of **splitting statements by newline characters before execution**. Passing complex, multi-line DDL can cause statements to be broken at unexpected points, leading to syntax errors. It is more robust to pass DDL as a single statement using `prepare(...).run()`.
- Use `all()` to fetch multiple rows and `first()` to fetch only the first row.

## Key Considerations for the Billing Model

The most critical metric to watch in D1's pricing structure is not the number of queries issued, but rather **the number of rows read from and written to disk**.

If no index is applied to the target column of a `WHERE` clause, the database performs a full-table scan. A single innocent search on a 100,000-row table incurs read charges for 100,000 rows. Do not neglect the design of `CREATE INDEX`.

| Operation Type | Free Tier          | Paid Plan                                          |
| -------------- | ------------------ | -------------------------------------------------- |
| Row Read       | 5 million rows/day | Up to 25 billion rows/month (included in base fee) |
| Row Write      | 100,000 rows/day   | Up to 50 million rows/month (included in base fee) |

The `env.DB` in the editor relays to a real D1 database over RPC, and the same SQLite query engine runs it. Only `prepare()` (with `bind()` / `run()` / `all()` / `raw()` / `first()`) and `exec()` are available; there is no `batch()` or `withSession()`. The database is shared by everyone on this site.

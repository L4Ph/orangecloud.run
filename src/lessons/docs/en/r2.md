# R2 (Object Storage)

For engineers receiving cloud infrastructure invoices, there is one item that inevitably draws a sigh of exasperation: **Egress (outbound data transfer) charges**. No matter how low the maintenance costs for the storage itself are, network transfer charges snowball every time large volumes of images or videos are downloaded.

Cloudflare R2 does not charge these outbound data transfer fees. No matter how many files are read, the charge for the volume transferred directly from R2 is zero.

## KV vs. R2: How They Differ

| Comparison Criteria | Workers KV                                                            | Cloudflare R2                                                           |
| ------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Minimum Unit        | Key and value (text/binary)                                           | Object (full file)                                                      |
| Capacity Limit      | Max 25MB per key                                                      | Max 5TB per object                                                      |
| Best Use Cases      | Configuration values, flags, short-lived caches                       | Images, videos, logs, backup archives                                   |
| Billing Structure   | Number of read, write, delete, and list requests + stored data volume | Stored data volume + number of operation requests (no transfer charges) |

## Essential Development Practices

- The basic operations are `put(key, streamOrBuffer)`, `get(key)`, `delete(key)`, and `list({ prefix })`.
- When extracting the body of a retrieved object, use `.text()`, `.arrayBuffer()`, or `.body` (which handles streams) depending on the use case.
- Reading a large file into a buffer consumes Worker memory all at once. Up to about 100 MB, pass a `ReadableStream` of known length (a request body with a `Content-Length` header, or a `FixedLengthStream`) to `put()`. For larger files, use a multipart upload (`createMultipartUpload()`).
- With Presigned URLs, end-user browsers can upload to and download from R2 directly, without going through Worker memory and bandwidth. The R2 binding cannot generate presigned URLs, so you sign them with S3-compatible API credentials (Access Key ID and Secret), for example with `aws4fetch`. They are valid for at most 7 days, need CORS rules on the bucket when used from a browser, and do not work with custom domains.

The `env.STORAGE` in the editor relays to the real R2 over RPC and differs from the production binding. `put()` stores a string, and `get()` returns the body as a string (or `null`), so you cannot call `.text()` on it. `list()` takes a prefix string (not `{ prefix }`) and returns an array of strings that pair each key with its size (for example `lesson/hello.txt (37B)`). The bucket is shared by everyone.

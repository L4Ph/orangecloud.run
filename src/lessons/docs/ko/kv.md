# Workers KV(키 밸류 스토어)

전 세계 수백 곳의 에지로 데이터를 즉시 복제하고, 극히 낮은 지연 시간으로 읽어온다——이렇게 들으면 만능 데이터 스토어처럼 보인다. 하지만 이 경이로운 읽기 속도는 **결과적 일관성(Eventual Consistency)**이라는 거대한 타협 위에 세워져 있다.

KV에 쓰기 작업은 먼저 중앙 스토리지로 전송되며, 그곳에서 각 데이터 센터로 비동기적으로 전파된다. 전파가 완료되기까지 최대 60초의 지연 시간이 발생한다. 도쿄 에지에서 쓴 최신 값을 같은 순간 런던 에지에서 읽었을 때 보인다는 보장은 없다.

## 적합한 용도와 부적합한 용도

- **적합한 것**: 설정값, 기능 플래그, URL 리다이렉트 테이블, 세션 정보 캐시, OGP 메타데이터 캐시(쓰기가 극히 드물고 읽기 빈도가 압도적으로 높은 데이터).
- **무너지는 것**: 재고 할당 카운터, 잔액 관리, 실시간 참가자 수 카운트(직전 업데이트가 반영되지 않으면 사고로 이어지는 용도).

## 기본 조작 및 사양상의 한계

- `get(key)` / `put(key, value)` / `delete(key)` / `list({ prefix })`
- 하나의 키에 저장할 수 있는 값의 크기 상한은 25MB. JSON 문자열이나 바이너리 캐시 용도로는 충분한 용량이다.
- 목록 조회는 전방 일치(`prefix`) 검색만 지원한다. 전체 훑기나 복잡한 필터링에는 취약하다.
- 과금 구조는 읽기에 비해 쓰기 비용이 더 높게 책정되어 있다(100만 회 쓰기당 5달러). 쓰기 빈도가 높은 설계는 비용 부담이 커진다.

에디터상의 `env.KV`는 학습용 샌드박스를 위해 실제 KV 인프라를 RPC로 중계한 것이다. 제공되는 메서드의 인수와 반환값 동작은 프로덕션 환경과 완전히 일치한다.

```js
await env.KV.put("user:1", "Alice");
const user = await env.KV.get("user:1"); // 'Alice'
const list = await env.KV.list({ prefix: "user:" }); // { keys: [...] }
```

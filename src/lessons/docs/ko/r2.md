# R2(오브젝트 스토리지)

클라우드 인프라 청구서를 받은 엔지니어가 절로 한숨을 내쉬는 항목이 있다. 바로 **Egress(외부로의 다운로드 데이터 전송) 과금**이다. 스토리지 자체의 유지비가 아무리 저렴하더라도, 대량의 이미지나 동영상이 다운로드될 때마다 네트워크 전송료가 눈덩이처럼 불어난다.

Cloudflare R2는 이 다운로드 데이터 전송 요금을 부과하지 않는다. 파일이 아무리 많이 읽히더라도 R2에서 직접 내보내는 전송량에 대한 과금은 제로이다.

## KV와 R2의 영역 분할

| 비교 축   | Workers KV                                       | Cloudflare R2                                     |
| --------- | ------------------------------------------------ | ------------------------------------------------- |
| 최소 단위 | 키와 값(텍스트/바이너리)                         | 오브젝트(완전한 파일)                             |
| 용량 제한 | 1키당 최대 25MB                                  | 1오브젝트당 최대 5TB                              |
| 최적 용도 | 설정값, 플래그, 단수명 캐시                      | 이미지, 동영상, 로그, 백업 아카이브               |
| 과금 구조 | 읽기·쓰기·삭제·목록 요청 횟수 + 저장 데이터 용량 | 저장 데이터 용량 + 작업 요청 횟수(전송 요금 없음) |

## 개발 시 숙지해야 할 관례

- 기본 조작은 `put(key, streamOrBuffer)`, `get(key)`, `delete(key)`, `list({ prefix })`이다.
- 가져온 오브젝트의 본문을 추출할 때는 용도에 따라 `.text()`, `.arrayBuffer()`, 또는 스트림을 다루는 `.body`를 구분해서 호출한다.
- 큰 파일을 버퍼에 읽어 들이면 Worker의 메모리를 한꺼번에 소비한다. 100MB 정도까지는 길이를 아는 `ReadableStream`(`Content-Length`가 있는 요청 본문이나 `FixedLengthStream`)을 `put()`에 넘긴다. 그보다 큰 파일은 멀티파트 업로드(`createMultipartUpload()`)를 사용한다.
- 서명된 URL(Presigned URL)을 쓰면 Worker의 메모리와 대역폭을 거치지 않고 엔드 유저의 브라우저에서 직접 R2로 파일을 업로드·다운로드할 수 있다. R2 바인딩은 서명된 URL을 만들 수 없으므로 S3 호환 API 자격 증명(Access Key ID와 Secret)으로 서명한다(`aws4fetch` 등). 유효 기간은 최대 7일이고, 브라우저에서 쓰려면 CORS 설정이 필요하다. 커스텀 도메인에서는 쓸 수 없다.

에디터상의 `env.STORAGE`는 실제 R2를 RPC로 중계한 것으로, 프로덕션 바인딩과 다르다. `put()`은 문자열을 저장하고, `get()`은 본문 문자열(없으면 `null`)을 반환하므로 `.text()`를 호출할 수 없다. `list()`는 접두사 문자열(`{ prefix }`가 아님)을 받아 키와 크기를 나란히 적은 문자열(예: `lesson/hello.txt (37B)`)의 배열을 반환한다. 저장 공간은 모든 사용자가 공유한다.

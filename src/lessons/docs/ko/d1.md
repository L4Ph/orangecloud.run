# D1(서버리스 관계형 데이터베이스)

서버리스 아키텍처에서 관계형 데이터베이스를 다루려 하면 오랫동안 두 가지 장벽에 부딪혀 왔다. 장거리 네트워크로 인한 통신 지연과 연결 풀(커넥션 풀)의 고갈이다.

D1은 **SQLite**의 SQL을 쓰는 서버리스 데이터베이스이다. 기본적으로는 한 곳의 프라이머리가 모든 쿼리를 처리하므로, 먼 로케이션에서는 통신 지연이 남는다. 리드 레플리카를 활성화하고 Sessions API(`withSession()`)를 쓰면 읽기 쿼리를 전 세계의 레플리카로 분산할 수 있다. 쓰기는 항상 프라이머리에서 실행된다.

## 쿼리 실행의 3원칙

```js
// 테이블 정의 및 마이그레이션 실행
await env.DB.prepare("CREATE TABLE IF NOT EXISTS notes (id INTEGER PRIMARY KEY, body TEXT)").run();

// 플레이스홀더를 이용한 안전한 파라미터 주입
await env.DB.prepare("INSERT INTO notes (body) VALUES (?)").bind("hello").run();

// 검색 결과 가져오기
const { results } = await env.DB.prepare("SELECT * FROM notes").all();
```

- 문자열 연결을 통한 SQL 구성은 엄격히 금지한다. `prepare(...).bind(...)`를 사용하여 이스케이프 처리를 드라이버에게 맡김으로써 SQL 인젝션 취약점을 제거한다.
- `exec()`는 **새 줄 문자로 문장을 분할하여 실행한다**는 특성이 있다. 여러 줄에 걸친 복잡한 DDL을 전달하면 예상치 못한 지점에서 문장이 끊겨 구문 오류가 발생한다. DDL 또한 `prepare(...).run()`으로 단일 문장으로 전달하는 것이 견고하다.
- 여러 줄 가져오기에는 `all()`, 첫 번째 줄만 추출하려면 `first()`를 구분하여 호출한다.

## 과금 모델의 핵심

D1의 요금 체계에서 가장 주의해야 할 지표는 쿼리 발행 횟수가 아니라, **디스크에서 읽어온 행 수와 쓴 행 수**이다.

`WHERE` 절의 대상 컬럼에 인덱스가 생성되어 있지 않은 경우, 데이터베이스는 테이블 전체의 모든 행을 스캔한다. 10만 행의 테이블에 대해 단 한 번의 무심한 검색이 10만 행 분량의 읽기 과금을 발생시킨다. `CREATE INDEX` 설계를 소홀히 해서는 안 된다.

| 작업 유형 | 무료 한도   | 유료 플랜                     |
| --------- | ----------- | ----------------------------- |
| 행 읽기   | 500만 행/일 | 250억 행/월까지 기본료 포함   |
| 행 쓰기   | 10만 행/일  | 5,000만 행/월까지 기본료 포함 |

에디터상의 `env.DB`는 실제 D1을 RPC로 중계한 것으로, 같은 SQLite 쿼리 엔진이 동작한다. 사용할 수 있는 것은 `prepare()`(`bind()` / `run()` / `all()` / `raw()` / `first()`)와 `exec()`뿐이며, `batch()`나 `withSession()`은 없다. 데이터베이스는 이 사이트의 모든 사용자가 공유한다.

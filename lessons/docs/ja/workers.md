# Workers の実行モデル

Worker は **リクエストが来るたびに呼ばれる関数**です。`fetch(request, env)` の戻り値がそのままレスポンスになります。

## 押さえるべき4点

1. **状態はリクエストをまたいで保証されない。** グローバル変数は isolate が再利用されている間だけ残ります。残したいなら KV / D1 / R2 / Durable Objects に置きます。
2. **ファイルもソケットも無い。** 外の世界へは `fetch()` とバインディング（`env.DB` など）で行きます。
3. **課金は CPU 時間。** ネットワーク待ちや `sleep` は無料。だから「外部 API を待つ」処理は安い。
4. **制限が先に来る。** メモリ 128MB、CPU は既定 30 秒（有料は最大 5 分）、同時実行数もプラン次第。無限ループは自分の Worker を殺します。

## 制限の目安

| 項目       | 無料     | 有料                  |
| ---------- | -------- | --------------------- |
| リクエスト | 10 万/日 | 1,000 万/月 + 従量    |
| CPU 時間   | 10ms/回  | 30 秒/回（最大 5 分） |
| メモリ     | 128MB    | 128MB                 |

まずは「毎回まっさらな部屋」というイメージで十分です。状態を持ちたくなったら次の単元へ。

```js
export default {
  async fetch(request, env, ctx) {
    // request / env（バインディング）/ ctx（waitUntil など）
    return new Response('hello');
  },
};
```

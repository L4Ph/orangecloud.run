# Workers KV（键值存储）

将数据即时复制到全球数百个边缘点并以极低的延迟读取——听起来像是一个万能的数据存储。然而，这种惊人的读取速度是以**事件一致性（Eventual Consistency）**这一巨大的妥协为前提的。

写入 KV 的数据首先被发送到中央存储，然后异步传播至各个数据中心。传播完成最多可能产生 60 秒的延迟。无法保证在同一时刻，从伦敦边缘读取到的值，与在东京边缘写入的最新值完全一致。

## 适用场景与不适用场景

- **适用场景**：配置值、功能标志、URL 重定向表、会话信息缓存、OGP 元数据缓存（写入极少，读取频率远高的数据）。
- **不适用场景**：库存拨付计数器、余额管理、实时参与人数统计（若未反映前次更新则会导致事故的场景）。

## 基本操作与规范限制

- `get(key)` / `put(key, value)` / `delete(key)` / `list({ prefix })`
- 单个键可存储的值的最大大小为 25MB。对于 JSON 字符串或二进制数据的缓存用途来说，这个容量绰绰有余。
- 列表检索仅支持前缀（`prefix`）查找。不擅长全表遍历或复杂的筛选。
- 计费结构设定为写入费用高于读取（每 100 万次写入 5 美元）。设计为高写入频率会增加成本。

编辑器中的 `env.KV` 是为了学习用沙箱而通过 RPC 中继实际 KV 基础设施的。提供的方法参数和返回值行为与生产环境完全一致。

```js
await env.KV.put('user:1', 'Alice');
const user = await env.KV.get('user:1'); // 'Alice'
const list = await env.KV.list({ prefix: 'user:' }); // { keys: [...] }
```
